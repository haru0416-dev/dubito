# dubito 自身への適用

日付: 2026-08-19。対象は家具プローブではなく、**dubito の検証層がすでに解いている数理計画**。

IR から定式化を機械生成しない。`dual.py` も YAML を CVXPY/OR-Tools に落とさない。ここでやるのは、その内部計画を物語から独立に書き直し、`verify()` で疑うこと。

## 探した場所

| 箇所 | 数理計画か | このプローブ |
|---|---|---|
| `dual.py` の LP 緩和と双対 | はい。いまは SciPy HiGHS 一本 | 当てる |
| `properties.py` の局所近傍 | はい。いまは格子列挙 / Hypothesis | 近傍を MILP にして当てる |
| `router.py` の層選択 | いいえ。クラス表の参照 | やらない。時間予算ナップサックにすると嘘になる |
| CEGIS / lessons | いいえ | やらない |

検証器が単一ソルバーだと、PLAN が定式化について警告している相関バグが、検証器自身に起きる。

## 1. 家具 LP の双対（`dual.yaml`）

`check_dual(furniture)` が SciPy で解いている双対を、物語から書き直す。

木材 12、労働 10。ミックスは `2*tables - chairs ≤ 0`（在庫 0）。非負の影の価格。

- テーブルを覆う: `3*wood + 2*labor + 2*mix ≥ 50`
- 椅子を覆う: `wood + labor - mix ≥ 20`
- 最小化: `12*wood + 10*labor`

独立な GLPK（CVXPY）と GLOP（OR-Tools）。YAML `verification` は import しない。植え込みバグは被覆を `≥` から `≤` にひっくり返す。

手計算の最適は `wood=10, labor=10, mix=0`、目的 220。これはオラクルであり、チェッカーへの入力ではない。

## 2. 局所近傍 MILP（`neighborhood.yaml`）

`properties.local_optimality` と同じ問いを最適化にする。既存の整数解 `(tables=2, chairs=6)` の L∞ 半径 2 の箱の中で、同じ工房制約のまま利益を最大化する。箱の外の欠労働点 `(0, 12, 240)` は入れない。

箱の中の最適が 220 のままなら、その半径で局所最適。Hypothesis のサンプルより強い（この箱では列挙可能）。

植え込みバグはミックスを逆向きにする。

## やらないこと

- `dual.py` を独立定式化のコンパイラに変えること
- ルーターをナップサックに置き換えること
- 内蔵 LLM
